# persist (saving, loading, undo, exports)

## Tested
All against SP\stage.html with pagecheck.py, PROFILE=prof-persist, BUDGET 12-30 s. Scripts in SP: `persist-rt.js` (plain -> JSON -> normalize deep diff, old sheet, 13 corrupt shapes), `persist-boot.js` (boots the raw old sheet left in ds-tabs), `persist-undo.js` (one pushUndo over wordsToNotes + applyTime + lockToSong(quiet,final,noUndo) + fill writes; undo/redo diff; 'lock' merge window; cap), `persist-export.js` (e2e2 fill + 40-slot note + drums/octaves; asText, musicXML via DOMParser, midiBytes via a MIDI parser, barTokens vs a mirror of partBar on 2527 random bars in 5 meters, score mode + @media print), `persist-storage.js` (touch debounce, sizes, setItem throwing), `persist-quota.js` (real quota, sheet grown), `persist-brick.js` + `persist-boot2.js` (one null line in ds-tabs), `persist-file.js` (File menu Save as/Open/XML/MIDI/Print/Duplicate with stubbed pickers), `persist-clear.js`.
Passing: round trip of 40- and 64-slot notes, 300 beats, spotify, filled, headers, rests, hy, drums, octaves, fixed frets: 0 field diffs, idempotent; old sheet defaults sane (xs 200 -> 60 so 64 total, pos filled after the note before, bars 0 -> 1, len 'x' -> q, filled null); one undo restores bpm/time/audio/lines/lyrics/title/filled and redo brings all back (only `forTrack:null` added); pushUndo('lock') x3 in 1.2 s = 1 step, new step after 1300 ms, cap 100 (UNDO_CAP); MIDI MThd/480 ppq/one track, 11 pitched + 23 drum (ch 10, 119 ticks) + piano pairs exact incl. the 40-slot note (off at on+4799); XML 8 measures each 16, ties 10/10, 40-slot tie chain, one lyric per syllable; barTokens == renderer on 2218/2218 bars in 4/4 3/4 2/4 6/8; renderScore clean, no chips/timeline/notehit/playhead in #scoreView, print CSS hides them; touch -> ds-store in 400 ms; file round trip exact, `format: dictation-sheet/2` written (never checked on open, harmless), garbage / {sheet:..} wrapper / null-line files refused with a toast.

## Findings
1. HIGH. Save silently lost at the localStorage quota, UI says "Saved in this browser". `persist-quota.js`: filled 4 MB + 112x8 KB, grew the sheet 20 -> 60 lines: ds-store and ds-tabs still 40.3 KB (old sheet), status "Saved in this browser [st ok]", dirty false, tab dot gone. Same with `Storage.prototype.setItem` throwing (`persist-storage.js`). Next boot reads the stale ds-tabs (line 4239) so the edits are gone. Budget: one 60-line placed sheet = 127.9 KB (273 chars/syllable), stored 3x (ds-store, ds-tabs, ds-versions) = 384 KB after the first save, up to ~2.8 MB once 20 versions accrue; origin quota measured ~5 MB, so two such sheets hit it.
2. HIGH (rare trigger, total effect). One `null` in `lines` (or a null syllable) throws in `normalize`, and `boot()` has no guard: `persist-boot2.js` shows cur() null, status stuck "Loading", empty tab bar, on every launch until site data is cleared (ds-tabs is never repaired). `persist-rt.js`: 11/13 corrupt shapes survive, `lines:[null]` and `syllables:[null]` throw. The file path is safe (toast "Could not open that file"), the boot path is not.
3. MEDIUM. 12/8: an empty bar exports as 16 slots, not 24. XML measures 24,16,16 for a 3-bar line; MIDI end of track 6720 of 8640 ticks (each empty bar pulls every later note 960 ticks early); 5/309 random 12/8 bars differ from the renderer, 0 in other meters. Place words makes empty filler bars routinely (line 3088), and the + bar button does too.
4. MEDIUM. `lined` flips back to true on load, undo, redo, Test exit, History restore: `normalize` sets `lined` true whenever offsetSec > 0, but `spUseTrack` (3200) sets lined=false and keeps offsetSec on a song switch. `persist-rt.js`: lined -> true; `persist-undo.js`: after undo lined true, offset 1. Then Lock no longer asks to line up bar 1 (2322) and Place words keeps the old song's bar 1 (3063, 2383).
5. LOW. asText columns shift when a cell is over 8 chars: `rquar.+10` (9) and `Ki+Sn+Ha+Cr` (11) pushed the rest of their rows by 1 and 3 (output in the run). `len` row does show `whol+24` for the 40-slot note.
6. LOW. musicXML throws "Cannot read properties of undefined (reading 'note')" when the first syllable of a line (by pos) has tie:true (3940, `order[oi-1]` with oi 0); exportMusicXML (4029) has no try/catch so nothing is saved and no toast. Editing tools keep order, so file-only.
7. LOW. Overlapping notes (a note running past the next onset; file or setSlotsRaw only): MIDI gets a double note-on and an orphan note-off for the carried pitch (3981 takes carry items when the token is mixed), and XML bar 2 carries the lyric "a" instead of "b" (3936 uses items[0]).
8. LOW. Edit then Ctrl+S within 400 ms: the pending debounced localSave fires after fileSave and sets "Unsaved changes, Ctrl+S saves the file", dirty true, dot shown, though the file has the current content (`persist-file.js`).
9. LOW. normalize keeps raw types: bpm "95" stays a string, text 5 stays a number (raw copy at 989/1004 comes after the String()); `sheetAudio()`'s default lacks `forTrack` so every load adds `forTrack:null`; in print the score's `.system` has no `break-inside: avoid` (only `.lineblock`, 406, and #scoreView is not inside one), so a system can split across pages.

## Root causes
1: `storeWrite` (1033) and `persistTabs` (1042) swallow the throw; `localSave` (1061) then sets the ok status and `dirty=false` unconditionally. Three full copies per sheet (1034, 1041, 4049).
2: `normalize` 1017 reads `l.bars` and 1003 `y.text` without a null guard; boot 4239 maps `normalize(x.sheet)` with no try/catch or fallback.
3: `barTokens` 3904 `slots: Math.min(pieceSlots(p), spb)` for the whole-bar rest (16 for a 24-slot bar); `partBar` 1310 uses `spb`.
4: `normalize` 994 `lined: !!d.audio.lined || (+d.audio.offsetSec > 0)`; every undo/redo/restore passes through normalize (1160, 1161, 3780, 4069).
5: 3811 width = max(text.length, 8) ignores the other rows. 6: 3936/3940 no `oi > 0` check. 7: 3981 and 3935 include carry items. 8: fileSave (3848) never clears `localSaveTimer`. 9: 989 and 1004 copy raw values after the typed defaults.

## Overlaps
- Report 1 (8 heads for 6 syllables): `barEvents` (860) draws a note crossing a bar line as a second tied head; the renderer, XML and MIDI agree (tokens == renderer), so two bar-line crossings give 8 heads by design. Only an overlap (7) would add phantom heads: worth checking the placed lengths (place-words / quantizeSpans part).
- Report 3 (bpm/time unchanged): `normalize` keeps `locked` whenever beats exist, so a lock survives reload/undo/redo/restore; `gridFromSong` (2366) then takes the `kept` branch ("Kept the lock at ...") and never re-reads the tempo; finding 4 keeps the old bar 1 too. Tempo/meter part: check `grid.kept` in the toast the user saw.
- Cloud save path (flush, 1064) not tested here.

## Fixes
1. Make `storeWrite`/`persistTabs` return false on throw; in `localSave` keep `dirty`, set status "Could not save, storage is full" (warn class) and toast once; on quota drop ds-versions and retry; store only ids in ds-tabs (as the cloud branch does) and cap versions by bytes, not count.
2. In `normalize`: `lines.filter(l => l && typeof l === 'object')` and the same for syllables; in boot wrap each `normalize(x.sheet)` in try/catch, skip the bad tab, rewrite ds-tabs, fall back to ds-store or the sample.
3. `barTokens`: `slots: (from === 0 && n === spb) ? spb : pieceSlots(p)`.
4. `normalize`: `lined: !!d.audio.lined` (one-time migration for old files: lined = offsetSec > 0 only when the key is absent), or have `spUseTrack` zero offsetSec.
5. width = max over every row's cell. 6. `slurStop = tk.first && y0.tie && oi > 0`; wrap exportMusicXML/exportMIDI in try/catch with a toast. 7. use only `!it.carry` items for note-ons and lyric text. 8. `fileSave`: `clearTimeout(localSaveTimer); localSaveTimer = null;` before writing. 9. `s.bpm = bpmClamp(d.bpm)`, `n.text = String(n.text)` after the copy, add `forTrack: null` to sheetAudio(); CSS `.score-body .system { break-inside: avoid; }`.

## Confidence
High on 1-5 and 8 (reproduced with numbers in the runs). Medium on 2's likelihood (needs a corrupt store) and on 6-7 (file-only shapes today). The report 1/3 links in Overlaps are from reading the code, not from a test.
