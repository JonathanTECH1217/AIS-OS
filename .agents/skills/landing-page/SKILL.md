# Landing page SOP (monarcbuild.com)

The governing file for every monarcbuild.com page. The site is built from two spec files Jonathan can edit, plus one theme file per look; this skill makes sure a build follows them and a finished page still matches them.

## Read first, in this order

1. `projects/Landing Page Build/Style Guide.md`: the invariants (layout, spacing, ratios, contrast, copy caps, media honesty, the ad-page bones) and the theme layer (section 8). Checkable rules are what `drift` tests.
2. `projects/Landing Page Build/Section Spec.md`: the homepage blocks, the `/av_marketing/` table, and the "Service pages" index.
3. For a service page: its theme file `projects/Landing Page Build/themes/<name>.json` (palette with measured contrast, faces, weights, the two labels, button, cards, the hero render) and its spec `projects/Landing Page Build/pages/<slug>.md` (block table, copy drafts with their approval column, images, budget, tile and render history).
4. `references/voice.md`, then `references/design-references.md`.
5. Facts only from canonical pages: `context/offer.md`, `context/about-business.md` (Proof jobs table and the PHA rule), `context/about-me.md`, `context/website.md` (pipeline, charset rule, live state).
6. If a rule in the spec is marked pending, use the named render placeholder and say so in the report. Do not decide a pending rule; Jonathan does. Open questions and the resume point: `brainstorms/2026-09-13-landing-page-sop.md` (house pages), `brainstorms/2026-09-25-google-ads-pages.md` (service pages).

## Modes

Pick from `$ARGUMENTS` or the request.

### build
Write or edit the page HTML in the local mirror `projects/monarcbuild-site/public_html/` (for the homepage, `index.html`). Rules:
- `<meta charset="utf-8">` is the first line inside `<head>` (encoding fix, 2026-09-09).
- Standalone CSS in the page or one stylesheet; palette values from the page's theme file only. Theme variables are scoped by `html[data-theme="<name>"]` in `public_html/assets/site.css`; the invariant CSS stays global.
- Images from `public_html/assets/`, relative paths, alt text on every one. Generated renders live in `assets/generated/<slug>/` and their alt text names them as illustrations.
- Keep the Google Ads tag block from the current `index.html`. Do not add or remove conversion snippets without asking.
- Run `drift` on the result before showing it, then `readability`. Fix what they find.
- Then run `render` and show the renders. Do not push. Pushing is a separate request through `scripts/site_sync.py` after Jonathan says go, and the old page moves to `archives/` first.
- Ad pages (`/av_marketing/` and any page with `<meta name="mb-page-type" content="ad">`) follow Style Guide section 6: no nav, three button instances that all open the booking popup and fall back to the calendar link, step buttons "OK", "Back", "Send", "Confirm appointment" carrying `data-step-btn`, the calendar step (6.10) with the drip behind it (`templates/booking-drip.md`), never "no setup fee". No timer bar and no scarcity claim (retired 2026-09-23). `drift.py` detects the meta and runs in ad mode (or pass `--type ad`). Render the popup and the sent states too: pass `file:///...index.html?step=4`, `?sent=1&at=<ISO>&booked=1`, and `?sent=1` URIs as the input; a `file:` URI (or `?static=1`) turns the reveal and count-up off so the render shows the page at rest.
- Service pages (Style Guide 6.16, added 2026-09-25) are ad pages in their own theme: `<meta name="mb-theme" content="<name>">`, the split hero with the theme's render, four static cards, one proof or walk-through block, the Works-for and Not-for columns in the theme's green and red, three FAQs, the final ask with the micro-line, the popup and sent state and footer and pill in the theme. Two labels: the hero label on the hero button and the pill, the final-ask label once. Build the v1 skeleton and nothing from the page's v2 list. No page is built before its style tile is approved.

### live
Jonathan shapes a page by talking here and watching a browser window. Four beats: he prompts, Claude updates the file, the window refreshes itself, Claude posts one line. He never opens a shell and never runs a thing.
- **Start it yourself.** On "landing page live", "open the preview", or any page change while a live session is on: fetch `http://127.0.0.1:8790/__live/version` (PowerShell `Invoke-RestMethod`, 2 s timeout). If it answers, the server is up; reuse it, do not start a second one. If not, start `python scripts/site_preview.py` with the shell tool in the background (`run_in_background`). The server opens the browser window on its own. Post the URL in one line. Other folders: `--root <folder>`; other first page: `--path /av_marketing/`.
- **The loop.** Jonathan says the change. Make one edit in the mirror `projects/monarcbuild-site/public_html/` with the Edit tool. The window reloads on its own (a CSS-only change swaps the stylesheet in place, no reload). Post one line: what changed, which file, which block. Then wait for the next prompt. No render, no drift, no extra work mid-loop. When he asks for ideas (sections, styling, scroll), offer them in batches of four with a recommendation marked, let him pick, and write the list and his picks to `brainstorms/YYYY-MM-DD-<page>-<topic>.md` (pattern: `brainstorms/2026-09-23-avmarketing-conversion.md`).
- **Hands off the tag.** Ask before touching the Google Ads tag block or any conversion snippet.
- **Style truth.** A shift to a type face, size, weight, or color goes into the page's theme file and Style Guide section 8 in the same turn, dated (house pages: Style Guide section 1 or 2). Page-level CSS goes in `public_html/assets/site.css` (linked after the build stylesheet on every page); never edit the one-line build file `assets/styles-Bf3p8a1Y.css`.
- **Still local.** Nothing is pushed. When Jonathan says he is done: run `drift` and `readability` on every touched page, `render` at 1440 and 390, and offer a `decisions/log.md` line for anything that moved a rule.
- **Stop.** Kill the background task when Jonathan says stop; it also dies with the session. He never has to close it.

### render
Full-page PNG at 1440 and 390 wide for approval in chat. Script: `.agents/skills/landing-page/assets/render.py <html> <out.png> <width>` (headless Chrome or Edge, then trims the blank tail). Save to `projects/Landing Page Build/renders/YYYY-MM-DD/`. Show the images with the Read tool, and note which rules in the render are placeholders. Ad page states: `file:///...index.html?step=4` opens form step 4, `?sent=1` the sent state, `?sent=1&held=<label>` the held-time sent state. In PowerShell write the URI as `"${uri}?step=4"`; `"$uri?step=4"` reads `$uri?` as a variable and renders a file-not-found page.

### drift
Compare a page against the checkable rules. Script: `.agents/skills/landing-page/assets/drift.py <html> [--type home|ad] [--theme <name>]`. It reads the page's theme from `<meta name="mb-theme">` (default house) and reports: h1 count, headline and sub word caps, em and en dashes, tenure claims, tier prices, PHA mentions, callback clocks, button labels and their counts (two hero-label instances and one final-ask instance on a service page), section anchor order, colors outside the theme, weights outside the theme, images without alt. Then read the page yourself for the rules the script cannot test (the theme's faces, one accent beyond the theme's list, real photos on proof and renders as illustrations only, the fit colors on headings and marks only, placeholder labels present where a rule is pending). Report findings by rule number from the Style Guide. Run before every push and whenever Jonathan asks "does the site match the spec."

### readability
Score a page against Copy 7. Script: `.agents/skills/landing-page/assets/readability.py <html> [--strict] [--json]`. Per section and for the page: words, sentences, longest sentence, Flesch-Kincaid grade raw and whitelisted (brand names and trade terms in `readability-exempt.txt`, plus any capitalized word not opening a sentence, count as one syllable), reading ease, the share of long words; the visible-word total outside the popup against the 6.16 budget. `--strict` fails on a whitelisted grade above 8 or a sentence over 25 words. Paste the summary into the page's spec. A brand or trade term the whitelist misses is one line in the exempt file, not a rewrite.

### tile
Render a theme's style tile for Jonathan's approval before any page in that theme is built. One template for every theme: `projects/Landing Page Build/tiles/tile.html?theme=<name>`, fed by `tiles/themes.js`, which `python scripts/ads_tiles.py` writes from `themes/*.json`. One page at 1440: the palette swatches and the measured contrast table from the theme file, the faces at the Style Guide scale, both buttons and the pill in the theme's shape, one What-you-get card with its opener, the Works-for and Not-for pair, a section label, one popup step and the footer in the theme, and the render candidates from `candidates/<slug>/` (labeled boxes where one is missing). `python scripts/ads_tiles.py --render [--theme <name>]` renders to `renders/YYYY-MM-DD/tile-<theme>-1440.png`; show it; record the date and his verdict in `pages/<slug>.md` under "Tile and render history". A change he asks for goes into the theme file and Style Guide section 8 first, then the tile is re-rendered.

### images
Run the generated-image batch for the service pages (Style Guide Media 1). First run: 2026-09-25, 56 generations, 112 credits, job ids in `projects/Landing Page Build/candidates/jobs-2026-09-25.json`.
1. Prompts from each theme file's `hero_render` and `card_renders`: the subject, the palette hexes, the shared style line ("stylized 3D cartoon render, soft matte clay-like materials... no text, no letters, no logos, no watermark; any person small, seen from behind or in silhouette"), 4:3 for a hero, 1:1 for a card. Record them in the jobs file.
2. Confirm the credit spend with Jonathan before submitting (`balance`; `get_cost` preflight; the connected generator has no free allowance on this account). Nano Banana Pro cost 2 credits an image at 1k and at 2k.
3. Submit with `generate_image_batch` (12 per call, four candidates per image as four requests), write each job id into `candidates/jobs-<date>.json`, wait with `jobs_wait`, and put each result's file name into `candidates/results-<date>.json`. A failed job is not charged; rerun it once with the same prompt and note the retry in the jobs file. The generator labels jobs `nano_banana_2` even when `nano_banana_pro` was requested; report it, do not hide it.
4. `python scripts/ads_images.py download candidates/jobs-<date>.json candidates/results-<date>.json` saves each candidate as a compressed JPEG in `candidates/<slug>/` (heroes 1600 wide, cards 800); `python scripts/ads_images.py contact <slug>` writes a contact sheet to `renders/<date>/candidates-<slug>.jpg`. Read every sheet before showing Jonathan: no text, no logos, no detailed faces, the palette held.
5. Re-render the tiles; Jonathan picks per image; `python scripts/ads_images.py pick <slug> hero <n>` and `pick <slug> card <k> <n>` export the pick to `public_html/assets/generated/<slug>/` (hero.jpg at 1600 and hero-800.jpg under 300 KB and 120 KB, card-<k>.jpg at 320 under 60 KB). Record the pick and the date in `pages/<slug>.md`. Never a photoreal scene presented as a job photo; never a mock result.

## Taste, built over time (Jonathan, 2026-10-05)

"The landing page skill gets kind of built over time based on my taste and how I change and adjust the landing page. Adjustments should also be recommended when there's big misses that could increase ... conversion rate heavily."

- **Read the taste log** on any build or edit, after the Style Guide: `projects/Landing Page Build/Taste Log.md`. It holds what he has changed on pages and the rule drawn from each.
- **Write to it in the same turn.** When he changes or adjusts a page (in `live`, after a render, or in a note), add one line: the date, the page, his words or the change, and the rule drawn from it. The rule is the AIOS's reading until he confirms it. A confirmed rule that can be checked moves into the Style Guide, dated, and into `drift.py` when a script can test it.
- **Use it on the next build.** Apply what the log holds, and name in the report each log line that shaped the page, so he can strike one that was meant for one page only.
- **Name the big misses.** After a build, a render, or a review of any page, his own or a prospect's, say which misses could move the conversion rate heavily: at most three, the costliest first, each with where it is on the page and why it costs leads. The test for "big" is in the taste log. Small polish is left out. A big miss is recommended, never fixed without his go.

### Rules he has said outright (they hold on every page built for a company, until he changes them)

- **A serif for high-end residential** (Jonathan, 2026-10-05): "companies targeting residential high-end should have a serif style font but it should be a light serif not too sharp and Victorian looking." Headings in a light, soft serif (weight 300 to 400). Not a sharp, high-contrast face: Cormorant Garamond is the kind he means to avoid. First used: Newsreader Light, with the company's own sans kept for buttons, eyebrows, and small labels. He picks from a rendered sample sheet when a new face is tried (`renders/2026-10-05/pha-serif-samples.png` is the first).
- **Credentials only in the footer** (same day): "High-profile companies don't need to post their credentials anywhere besides in the footer." No dealer badge or award in the hero, the about section, or anywhere above the footer. A Google rating beside the ask is proof, not a credential, and stays. Press is not a credential either: the same evening he put "Projects featured in Architectural Digest and Annapolis Home Magazine" as the line at the top of the hero, in the brand's color with nothing behind it (he took out a pale chip the same evening: "Take out the white background behind the text for the eyebrow"). On a dark photo use the deepest shade of the brand color that still measures 4.5 to 1.
- **Reviews come from the Google Business Profile, with no last names** (same day): "Reviews from the Google My Business profile and post them to the reviews section" and "do not include last names in the reviews that are shown." Read the profile once through the Places API (`GOOGLE_MAPS_API_KEY`, a few cents; it hands out five reviews at most, plus the rating and the count). Show a first name and a last initial. Every sentence shown is word for word; a long review is shortened by leaving whole sentences out. Pick the reviews that fit the page's service first.
- **Photos from the company's own profile** (same day, on the second page): the Google Business Profile's photos are fetched the same way and are the first place to look for a real hero or job photo.

## Prospect renders (2026-10-06)

A render is the page a company should have, built from Jonathan's Loom audit of their site, never pushed anywhere. PHA and Momentum were built by hand (2026-10-05); since 2026-10-06 ("Use these links to build the renders", fifteen audits at once) every render comes from one engine, so his notes on one page reach all of them.

- **The engine:** `python scripts/prospect_page.py all <slug>` reads `prospects/<slug>/spec.json`, writes `index.html` beside it, and renders `renders/<date>/<slug>-after-1440.png`, `-fold-1536.png`, `-390.png`. The spec's fields are in the script's docstring; `prospects/_engine-test/spec.json` is the PHA page as a spec. Sections: hero, cards, about, process, work, reviews, services (the secondary services he asks for, linked to their pages), faq, final; `order` follows what he said in that Loom. `hero.light` is the pale scrim with dark words he asked for once (Tru Definition). His A B A C A B A background rule is on by default: A is the hero's ground, B its opposite, C the brand color pushed toward A (`band_colors`); a spec's `pattern` may set A, B, or C, or `"off": true`.
- **What goes in a spec:** his words first (the service, the place, the eyebrow, the cards, the color he named, the order), then the company's own site (`research.py site`, free: name, phone, address, colors, faces, their words, their photos). Nothing invented: no rating, year, award, or count that is not on their site. Anything missing draws a marked empty box (a review, a job photo, the owner's photo). The Google review pull is a few cents a company and waits on his go.
- **Beside every render:** `brief.md` in the Momentum brief's shape (the page, how to see it with `site_preview.py`, the Loom, what he said at each time and what the page does, where every fact came from, the three big misses). The batch record is `prospects/audits-2026-10-06.md`.
- **After the render:** he records the second half of the Loom over it, and `/loom-b-and-a` cuts the before and after.

## House rules this skill enforces

- Never name PHA or Performance Home Automation, never link pha.systems.
- Never print `$2,500` or `$4,500`. Proof numbers are fine.
- No tenure claim, no em dashes, no callback clock. The button labels come from the page's theme: house pages "Book an appointment"; the homepage "Book an appointment" (theme `monarc`, 2026-09-27; the old "Book a 15 minute call" retires with the old homepage); service pages their two labels.
- No stock images anywhere. Generated renders are designed visuals in the theme's palette, never a job photo or a result. Third-party marks appear as product names in text only, never as a logo in a hero or as a brand mark.
- External copy is a draft until Jonathan approves the render (`CLAUDE.md`, Voice). Every copy line in a service page's spec carries an approval column.
- Update `context/website.md` when the live site actually changes, not before.
- When a service page goes live, add it to `LIVE` in `scripts/services_menu.py`, rerun it, and push `about/index.html` and `book/index.html` on Jonathan's go, so the Services menu lists it (Section Spec, "Services menu"). The homepage (round 3, 2026-09-27) carries the services as its six cards instead: add the card in `build/home.body.html`, run `python scripts/ads_images.py thumbs` (it writes the card picture, `tile.jpg`), and rebuild with `python scripts/build_service_page.py home --force` (writes `public_html/index.html`, pushed with a plain `push`; the old `live/index.html` copy and `push-as` retire when it ships).
- `/about/` is built from parts too (2026-09-27): `python scripts/build_service_page.py about` (`build/about.body.html`, `build/about.css`). Each service page's body carries `<!-- other-services -->` above the footer, filled with links to the other five; a new service page is added to `SERVICES` in the build script and to the six cards in `home.body.html` and `about.body.html`.
- The logo banner (2026-09-28, `brainstorms/2026-09-28-landing-pages-banner.md`): the homepage and each service page carry `<!-- logo-banner -->` under the hero, filled by `logo_banner()` in the build script: the label "We list your business on" (never "We work with", Style Guide Media 7), the big marks (`logos-lg` in `site.css`), and no platform's logo on the page that sells its ads (`LOGOS_LEFT_OUT`). `/av_marketing/` carries it by hand after its services (`templates/logo-banner.html`); edit and push it from `projects/monarcbuild-site/staging/av_marketing/index.html`.
